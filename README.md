# CaptureEvidence

CaptureEvidence makes protein-group coverage comparisons inspectable. It links
condition-level counts to the original culture columns, full protein identifiers,
control overlap and MS/MS evidence. It is a companion analysis tool for affinity
proteomics, including the MCP4 cleavable tetrazine comparison.

## Open the application

Download **CaptureEvidence.html** and open it in a current browser. It runs entirely
offline, without Python, Node, a server, an account or installation. Public builds
contain an explicitly synthetic example. The manuscript companion package contains
the MCP4 export and sample map. No data are transmitted or persisted by the app.

Self-extracting packages unpack the application into a new folder on the Desktop
and open it. Existing folders are never overwritten. macOS packages and Windows
executables are unsigned; the HTML file is also directly usable.

## What it computes

* Positive LFQ presence; or positive LFQ plus MS/MS in the same culture column.
* Optional global requirement of at least two peptides and one unique peptide.
* At least one, two or more supporting cultures in each condition.
* Symmetric exclusion of the C2 LFQ union or combined C1/C2 LFQ union.
* Set size, shared membership, condition-only groups and PEG retention.
* Every omission of one SS and one PEG culture, using the remaining unions.
* CSV membership exports and full JSON reports including source SHA-256 and rules.

The global peptide filter is not a per-culture two-peptide requirement. Omission
scenarios are overlapping descriptive comparisons, not extra replicates. Zero LFQ
values indicate unquantified observations and are never imputed. The program does
not infer abundance changes from counts, search spectra, calculate FDR, establish
site localization, or resolve proteins within a protein group. GLY membership is
based solely on a substring in the original majority identifier field.

## Load data

Use **Load another export**, paste or edit the JSON sample map, then choose a
MaxQuant proteinGroups TXT/TSV file. A map entry has this form:

```json
{"cell":"Model A","condition":"SS","culture":1,"column":"38"}
```

Provide SS, PEG, C1 and C2 sample blocks for each model. Column numbers identify
`LFQ intensity 38` and `MS/MS count 38`, for example. Cultures must represent
independent preparations; reinjections must not be entered as biological replicates.
The importer rejects missing required columns, invalid numbers and duplicate IDs
or sample mappings. Blank numeric export fields are treated as zero evidence.

## Reproduce or adapt

Node 20 or newer is needed only for development or command-line use. No npm
packages are required.

```sh
node --test core.test.js
node build.js
node cli.js proteinGroups.txt sample-map.json options.json > analysis.json
```

Example options:

```json
{"cell":"MDA-MB-231","category":"all","rule":"direct_peptides","minimum":2,"control":"both"}
```

Build output is `dist/CaptureEvidence.html`. An optional first argument to
`build.js` supplies a validated data JSON bundle instead of `demo.json`.
`validate-study.js` independently compares the JavaScript engine with frozen
S13/S14 CSV tables generated by the original Python pipeline:

```sh
node validate-study.js /path/to/MCP4 sample-map.json mcp4-data.json
```

Version 1.0.0 reproduced all 72 culture-threshold and 216 omission scenarios of
the MCP4 source package. The input proteinGroups SHA-256 is
`e54e7f4c0b61543ee5453c1dcb7d1fd15075e3f46125148ebd22f9aa35872ee6`.

## Build self-extractors

The Go launcher embeds `payload.zip` containing the application and README. Go
1.24 or newer is required. Run `go test ./...`; use `GOOS=windows GOARCH=amd64 go
build -o CaptureEvidence-Windows.exe .` or the corresponding `darwin` target.
`--extract NEW_DIRECTORY --no-open` verifies extraction without opening a browser.
The launcher checks archive paths, rejects symlinks, limits extracted size and
refuses existing destinations. No elevated privileges are needed.
